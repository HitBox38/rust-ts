`#[derive(Diagnostic)]` / `#[derive(Subdiagnostic)]` generated by `tools/codegen`, verified against the
real rustc_macros expansion; `rustc_parse/src/diagnostics.rs` generated + hand fns ported.

## Pin facts that differ from the brief
- At the pin the files are `compiler/rustc_parse/src/diagnostics.rs` and `compiler/rustc_session/src/diagnostics.rs`
  (no `errors.rs`). Per PORTING §2 the TS files mirror that: `src/rustc_parse/diagnostics{,.gen}.ts`.
  **Decision for root to record:** "codegen-diag: rustc_parse/rustc_session errors.rs is diagnostics.rs at the pin; TS files mirror it".
- Messages are inline Fluent strings (`#[diag("...")]`, `DiagMessage::Inline`), no slugs/ftl. `LintDiagnostic` and
  `#[skip_arg]` do not exist at the pin. Attribute set (rustc_macros/src/lib.rs:181-213): Diagnostic: `diag`, `help`,
  `help_once`, `note`, `note_once`, `warning`, `primary_span`, `label`, `context`, `subdiagnostic`, `suggestion`;
  Subdiagnostic: those + `multipart_suggestion`, `suggestion_part`, `applicability`.

## Files
- `tools/codegen/diagnostics.ts` (new): port of rustc_macros/src/diagnostics/{diagnostic,diagnostic_builder,
  subdiagnostic,utils,message,error}.rs (msg_macro.rs = `msg!`, used by hand code as an object literal). Each upstream fn
  carries `// rustc_macros: diagnostics/<file>:<line> <fn>` (not `// rustc:`; rustc_macros is excluded from coverage).
  The macro's attribute parsing runs over the probe's attribute token trees with a small syn `ParseStream` stand-in;
  output is a statement IR mirroring the `quote!` output 1:1, with two renderers: `renderTs` (the .gen.ts code) and
  `renderRust` (for verification). Macro compile errors (`span_err(..).emit()`, `throw_*!`, syn errors) become
  generator errors (types.ts exits 1). Fluent variable references use the vendored fluent_syntax parser.
- `tools/codegen/diag-expand.ts` (new): builds a scratch crate ($RUST_TS_DATA/tmp/diag-expand) with upstream
  `rustc_macros`, runs `cargo +nightly rustc -- -Zunpretty=expanded`, tokenizes every generated `match self` arm,
  canonicalizes (`DiagMessage::Inline` and `format!`/`format_args!` by value, `__code_N` renumbered) and compares with
  the IR. `bun tools/codegen/diag-expand.ts rustc_parse compiler/rustc_session/src/diagnostics.rs [--write-fixture]`.
- `tools/codegen/types.ts`: hook `emitDiag` after each struct/enum (impls emitted right after the type); `DiagTsCtx`
  implementation (IntoDiagArg/Display via `diag_args.json`, Subdiagnostic fns of field types incl. manual impls from the
  hand module, error-code constants from rustc_errors/lib.ts); `PAttr.tokens/line/col`; report `missing_diag_arg`,
  per-file `diag_impls`; `unported_into_diag_arg` / `unported_display` helpers for unmapped types.
- `tools/codegen/diag_args.json` (new): Rust type -> `IntoDiagArg` fn / Display template (String, str, Cow, bool, char,
  integers, Symbol, Ident, Edition, Path, PathBuf).
- `tools/codegen/typemap.diag.json` (new): `rustc_ast::token::{Token, MetaVarKind}`, `rustc_errors::{Applicability
  (-> src/rustc_lint_defs), MultiSpan, DiagMessage}`, `std::path::Path`.
- `tools/codegen/types.sets.json`: set `rustc_parse` (merged with main's `rustc_lint_defs`).
- `tools/probes/typedefs/main.rs`: list attributes get `tokens` (token trees; string literal value + suffix decoded by
  syn; line/col per token); every attribute gets `line`/`col` of its `#`. Additive; rebuilt.
- `src/rustc_parse/diagnostics.gen.ts` (generated, 7.5k lines), `src/rustc_parse/diagnostics.ts` (hand, 12/12 fns).
- Tests: `tools/codegen/diagnostics.test.ts`, `src/rustc_parse/diagnostics.test.ts`; fixtures
  `tools/codegen/fixtures/{rustc_parse,rustc_session}.typedefs.json`, `diag-expansion.json`.

## Generated TS shape
`T_into_diag(self, dcx, level): Diag` + `T_diagnostic(self): Diagnostic`; `T_add_to_diag(self, diag)` +
`T_subdiagnostic(self): Subdiagnostic` (same convention as rustc_errors' `SingleLabelManySpans_*`). Bodies destructure
`self` into `__binding_N` and then make exactly the expansion's calls in its order: `Diag.new(dcx, level, {$:"Inline"})`,
suggestion code inits, preamble (`code`, struct-level note/help/warn), `diag.arg(name, IntoDiagArg.of(v, fn))` for fields
referenced by any message, then field attributes in field/attribute order (`span`, `span_label`, `span_note`,
`span_suggestions_with_style`, `subdiagnostic`, Option -> `if (b !== undefined)`, Vec -> `for`, bool -> `if`).
Subdiagnostics: `suggestions` vec, code inits, field attrs (`suggestion_part` pushes, nested `add_to_diag`), `sub_args`
(DiagArgMap of used plain fields), then per kind `format_diag_message(msg, sub_args)` + `diag.<kind>` call.
Quirks kept: `used_fields` shared across the variants of a Subdiagnostic enum; `#[applicability]` field taken by the
first suggestion only; `build_format` arguments sorted (BTreeSet).

## PORT: decisions
- Inherent fns of generated types: companion const re-defined in the hand module (`ExprParenthesesNeeded.surrounding`,
  `ExpectedIdentifierFound.new`, `UnexpectedTokenAfterStructName.new`, `HelpUseLatestEdition.new`,
  `TokenDescription.from_token` on `{...gen.TokenDescription}`), like rustc_ast/token.ts.
- `msg!("..")` in hand code -> `{ $: "Inline", _0: ".." }`. `Vec<Span>.clone()` -> `.slice()`; String clones dropped.
- `verify_message_style` uses JS `\p{Uppercase}` for `char::is_uppercase` (only affects generator error checks).
