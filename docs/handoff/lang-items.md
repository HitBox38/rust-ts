# Handoff: lang-items (wave 14, M3a)

Branch `lane/lang-items`, based on main 935a15a. Not merged, not pushed.

## Result
`tcx.lang_items()` and its helpers work. This covers the `get_lang_items` query, the `TyCtxt` methods in
middle/lang_items.rs, `LanguageItems::set` / `from_def_id`, and weak lang item checking. `Target::is_abi_supported`
is ported. The lowering lanes can now call `lang_items`, `fn_trait_kind_from_def_id`,
`async_fn_trait_kind_from_def_id`, `require_lang_item`, `is_abi_supported`, and so on.

At the pin, `LanguageItemCollector` walks the **AST** through `tcx.resolver_for_lowering()`, not the HIR. So it does
not depend on lane middle-hir.

The driver reaches `get_lang_items` only from `lower_to_hir` (lanes lower-*). The new oracle test therefore uses its
own runner, which calls `tcx.lang_items()` in `after_expansion`. It is compared with a new rustc-dev probe that does
the same thing in the oracle compiler.

## PORT decisions
- `LanguageItems.reverse_items` (`FxIndexMap<DefId, LangItem>`) is a `DefIdMap`.
- `impl Visitor for LanguageItemCollector`: the class extends `visit.Visitor`. The trait methods are assigned to the prototype after `get_lang_items`, which keeps upstream order.
- `crate_extern_paths(..).map(|p| p.display().to_string())` uses the path string itself.
- `extern_crate` (query value typed `unknown`) is cast to `ExternCrate | undefined`.
- weak_lang_items `verify`: `FxHashSet<LangItem>` becomes a `Set`. It is only probed, never iterated.
- `rustc_passes::provide`: the modules that are not ported are skipped, with the existing `debugger_visualizers` placeholder kept.

## Notes for root / other lanes
- Not covered: `Target::is_abi_supported` has no oracle evidence yet. It is a two-line wrapper over the already-tested AbiMap. Its callers (ast_lowering E0570, etc.) arrive with the lower-* lanes.
- Not covered: the `delayed_bug` in `check_for_lang` (wrong target) is not compared. The probe stops before the attribute parser emits the real error, so the oracle ICEs on the delayed bug.
- Merge conflicts: lowering lanes that stubbed `lang_items` / `fn_trait_kind_from_def_id` / `require_lang_item` with `unported_methods` must drop those stubs. The real methods are now on `TyCtxt.prototype`.
- Merge conflicts: any lane that also adds a codegen set for rustc_passes or rustc_middle diagnostics conflicts with the two sets here.
- `ty_ordering_enum` (context.rs:1000) is still not ported; it needs `type_of`.
