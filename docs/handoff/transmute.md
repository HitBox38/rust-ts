## PORT decisions

- **Hand-written types.** The crate's types are written by hand rather than generated by tools/codegen. They are small and generic over `R` / `T`, and none needs Decodable / HashStable / TypeFoldable. Derived `Debug` is `debug_*`; derived `PartialEq` is `Answer_eq` / `Tree_eq` / `Dfa_eq` (intern key for `R` / `T` / `D` payloads); derived `Clone` is `clone_Answer` / `clone_Condition` / `clone_Tree` / `clone_Dfa` / `clone_Byte`.
- **Traits.**
  - `Region` / `Type` are erased. Equality and hashing use the intern key; `Debug` is passed in as a function.
  - `layout::Def` is a method table `Def<D>`.
  - `QueryContext` is a table `QueryContext<D, R, T>` whose `Def` is the impl of the associated type. `answer_tree` takes the table of `C` (`QueryContext_TyCtxt` / `test.QueryContext_UltraMinimal()`).
- **`answer` split by `L`.** The three `MaybeTransmutableQuery::answer` impls (for `Ty` / `Tree` / `Dfa`) are `answer_ty` / `answer_tree` / `answer_dfa`. Every call site knows `L` statically.
- **`and` / `or` placement.** `impl Answer { and, or }` (in maybe_transmutable/mod.rs) is `AnswerExt` in that file. The `Answer` companion lives in lib.ts, which imports that module, so attaching the methods to it would be order-dependent at module init.
- **Ownership.**
  - `Tree::then` / `or` and `Answer::and` / `or` append to their arguments' vectors in place, as upstream.
  - Every Rust clone is a fresh value: `vec![t; n]`, `repeat_n`, `answer.clone()` in the memo cache, and the tests' `.clone()`.
  - `Byte` copies that get written (`EdgeSet::iter`'s `.copied()`, mutated through `UnionIter`'s `peek_mut`) are `clone_Byte`.
- **Module shapes.**
  - `State(u32)` is a branded number. `State(n)` is `State.of(n)`; the global counter is a module `let`.
  - `#[cfg(feature = "rustc")] mod rustc` is `namespace rustc` in layout/mod.ts and tree.ts (holding `Def`, `layout_of`, `Err`). In tree.ts, the `impl Tree` methods of that module are on the `Tree` companion.
- **Iterators.**
  - They stay lazy (generators) wherever upstream short-circuits: `Quantifier::apply` via `try_fold`, and `from_tree`'s `Alt` fold.
  - `EdgeSet::iter` / `bytes_from` build their copies up front (an array iterator, for speed); copying has no side effects.
  - `Peekable` is a local minimal port.
- **Pair keys.** `state_pair_key` is a number while both states are below 2^26 and a string otherwise; the two kinds never collide.
- **Test init order.** The test files import `../rustc_middle/lib.ts` first. Loading `rustc_transmute/lib.ts` before any rustc_middle module trips an existing rustc_middle init-order TDZ (`BoundRegionKind` in rustc_type_ir/binder.ts). The driver always loads rustc_middle first, so only tests are affected.
- **Slow `nonzero` test.** `maybe_transmutable/tests.rs:453 nonzero::should_permit_identity_transmutation` builds a 65,535-state DFA for width 16. That takes a few seconds in TS, so the test has a 60s timeout. `Tree::nonzero` is dead code in rustc itself (`#[allow(dead_code)]`), so this does not affect compilation.
