## Summary
- **`builder.rs` is ported in full (146/146), and `allocator.rs` too (2/2).** Both are in upstream order, with markers. All 151
  cg-builder stubs from cg-contract are replaced. The port covers:
  - every `BuilderMethods` and `StaticBuilderMethods` method;
  - the `Has*`, `LayoutOfHelpers` and `FnAbiOfHelpers` forwarders;
  - `Drop`;
  - every inherent method of `GenericBuilder`, `SBuilder` and `Builder`. That includes `with_cx`, `direct_alloca`,
    `position_at_start`, `check_call`, `phi`, `add_incoming_to_phi`, `SBuilder::call`, `generate_ubsan_cfi_diag_data`, the
    metadata helpers, `write_operand_repeatedly_{optimized,unoptimized}`, the vector reductions, `call_intrinsic`,
    `call_lifetime_intrinsic`, `landing_pad`, `callbr`, `cfi_type_test`, `kcfi_operand_bundle`, `ptrauth_operand_bundle` and
    `instrprof_increment`.
- **Inherent before trait (decision 2026-11-11):**
  - Every call site where upstream resolves to the inherent method uses the `_inherent` name. Those sites are:
    - `volatile_load` and `load_operand` call `load_inherent`, so there is no alignment clamp;
    - `unchecked_{u,s}trunc` call `trunc_inherent`;
    - `tail_call` calls `ret_void_inherent` and `ret_inherent`;
    - `check_call` calls `bitcast_inherent`;
    - `write_operand_repeatedly_unoptimized` calls `inbounds_gep_inherent`;
    - `Self::build(..)` calls `build_inherent`, in `switch_to_block` and both `write_operand_repeatedly_*`;
    - `Self::append_block` calls `append_block_inherent`, in `append_sibling_block`;
    - `vector_splat`'s `self.const_null(..)` calls `const_null_inherent`. The receiver autoderefs to `CodegenCx`, where
      `GenericCx::const_null` (inherent) wins.
  - In allocator.rs, `SBuilder::build`, `bx.ret` and `bx.ret_void` are the inherent methods.
  - The builder.ts header lists all of these.
  - A test checks that `load`/`store` clamp the alignment and `load_inherent`/`store_inherent`/`volatile_load` do not.
- **Size:** builder.ts is 2,314 lines, of which about 2,100 are the port. allocator.ts is 183 lines.
- **Not registered:** nothing outside `src/rustc_codegen_llvm/` imports the crate yet, so no driver path changes. The samples
  below show this.

## IR-model stops that builder.rs reaches (left as is)
- `LLVMBuildCallBr` (stub). Called by `callbr`, which is asm goto (cg-asm).
- `LLVMReplaceMDNodeOperandWith` (stub). Called by `br_with_attrs` when there are loop hints (`#[unroll]`), after the metadata
  node is built. Tested.
- `LLVMRustBuildVScale` (stub). Called by `vscale`, for scalable vectors. Tested.
- `llvm::HasStringAttribute`: `llir: LLVMRustHasFnAttribute` (cg-contract's llvm/mod.ts stop). Reached by `cfi_type_test` and
  `kcfi_operand_bundle` only when `-Zsanitizer=cfi` / `kcfi` is on.
- **Model gap (for the llir lanes), not a stop.** `LLVMBuildAtomicRMW` and `LLVMBuildAtomicCmpXchg` leave the alignment unset, so
  the printer prints no `, align N`. LLVM's IRBuilder sets it to the type's store size from the DataLayout, and the oracle prints
  `, align 4`. builder.rs sets no alignment on these instructions, so this is the model's gap. The M7 normal form (an `opt` round
  trip) restores the alignment, as the verify test shows. Byte-identical pre-normalisation text would need the model to set it.

## `// PORT:` decisions (for root to record)
1. **`*self = Self::build(self.cx, llbb)`** assigns the new builder's three fields to `this`. This happens in `switch_to_block` and
   both `write_operand_repeatedly_*`. The span therefore goes back to `DUMMY_SP`, as upstream (tested). The old builder's `Drop` is
   not run (cg-contract decision 12).
2. **`with_cx` and `build_inherent`** are statics whose `this` is the subclass constructor (`GenericBuilderCtor<CX, Self_>`), so
   `Builder.with_cx(cx)` / `Builder.build_inherent(..)` are typed `Builder` and `SBuilder.build_inherent(..)` is `SBuilder`.
   `Self::with_cx(cx)` inside `build_inherent` is `with_cx.call(this, cx)`.
3. **Macro-generated methods** carry `// PORT: generated by <macro> (builder.rs:267|277) for <name> (builder.rs:<line>)`. This is
   the rustc analogue of PORTING §5c's rule for LLVM macro-generated functions.
4. **`scalar_load_metadata`** (builder.rs:747) is a nested function inside `load_operand`, where upstream has it, with its marker.
5. **`check_call` returns `readonly Value[]` for `Cow<[&Value]>`.** When every argument matches, it returns the same array, which
   stands for `Cow::Borrowed` (tested). Upstream uses `iter::zip`, which stops at the shorter of the two sequences; the TS loops do
   the same.
6. **Numbers:**
   - `align.bytes() as c_uint` is `align.bytes()` (at most 2^29);
   - `size.bytes() as c_uint` (atomic alignment) is `size.bytes() >>> 0`;
   - sizes passed on as `u64` use `bytes_u64()` (`type_array`, `const_usize`, `call_lifetime_intrinsic`'s zero test);
   - `range.end.wrapping_add(1)` is `BigInt.asUintN(128, ..)`;
   - `0xffffu16 as i16` is `(0xffff << 16) >> 16`.
7. **`fn_abi.conv != CanonAbi::C`** compares the `$` tags. `C` carries no data.
8. **`std::ffi::CString::new(name).unwrap()`** in `direct_alloca` is the local `unwrap_cstring`. It panics with `NulError`'s
   `unwrap` text on an interior NUL.
9. **`tcx.data_layout`** (a field upstream) is `tcx.data_layout()`, the TS accessor. `self.tcx` on a Builder is the forwarded
   `FullCx` field (`this.tcx`). `memcpy`'s `add_tt(self, ..)` passes `this.cx_._0`, because `&Builder` deref-coerces to
   `&FullCx`.
10. **`debug!` and `#[instrument]`** (tracing) are comments.
