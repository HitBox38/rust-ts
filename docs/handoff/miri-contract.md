## Decisions (for root to record with `bun scripts/state.ts record decision`)

- **C1 layout.** `src/tools/miri/src/<path>.rs` → `src/miri/<path>.ts` (+ `.gen.ts`); markers
  `// rustc: src/tools/miri/src/<path>.rs:<line> <name>`. The `miri` binary (`bin/miri.rs`, `bin/log/*`) is its own crate
  (`miri(bin)` in stub paths): `src/miri/bin/*.ts`, not loaded by `src/miri/lib.ts`, and not in the codegen set (its few
  types are hand-written by miri-driver: `bin/miri.rs` `use`s the library as `miri::`).
- **C2 extension traits.** `trait EvalContextExt<'tcx>: MiriInterpCxExt<'tcx>` + `impl EvalContextExt for MiriInterpCx {}`
  (one or two per file, also `EvalContextPrivExt` / `EvalContextExtPriv`) → `declare module ".../eval_context.ts" { interface
  InterpCx<M extends Machine = Machine> { name(this: MiriInterpCx, ..): R } }` in the file's own module, bodies assigned on
  `InterpCx.prototype` (PORTING §5). `let this = self.eval_context_mut();` → `const this_ = this.eval_context_mut();`
  (PORTING §4 reserved `this`). 390 extension methods declared (+ `MiriInterpCxExt`'s 2, ported), none colliding
  (checked at load).
- **C3 `MiriInterpCx`.** `InterpCx<Machine & MiriMachine>` until interp-generic, then `InterpCx<MiriMachine>`
  (`PORT(contract)` in machine.ts).
- **C4 `BorTag`** is a branded `number` (one tag per retag/allocation, < 2^53), methods on the companion.
- **C5 u64/i64 are `bigint` in set `miri`** (set-local typemap): addresses, sizes, user data written to program memory
  (epoll data, eventfd counters, inode numbers) — the interpreter's own convention. A fill lane may retype a
  provably-small hot field with a `fields` entry (followups-34 mechanism) and a `PORT:`.
- **C6 built without `native-lib`.** The rustup component has Miri's default features (`stack-cache`, `native-lib`); the
  port is generated as without `native-lib` (`typemap.miri.json` cfg), since shims/native_lib is out of scope (D2). With no
  `-Zmiri-native-lib` flag the two builds behave the same (`allocator` is `None`, `native_lib` empty: alloc_addresses
  :166/:190, machine.rs:820/:842, foreign_items.rs:266 are only reached with a native lib). `-Zmiri-native-lib` must stop
  `unported` (bin/miri.rs:343, machine.rs:844), not print the not-enabled panic.
- **C7 genmc.** The component is built without `genmc`, so `mod genmc` *is* `concurrency/genmc/dummy.rs`
  (`#[cfg_attr(.., path = "genmc/dummy.rs")]`): in scope (miri-threads), the rest of genmc out.
- **C8 `binary_ptr_op_`.** Miri's `operator::EvalContextExt::binary_ptr_op` shares its name with rustc_const_eval's private
  inherent `InterpCx::binary_ptr_op` (operator.rs:316; Rust resolves Miri's calls to the trait method because the inherent
  one is private). In TS both live on `InterpCx.prototype`, so Miri's is `binary_ptr_op_` (the trailing-`_` clash rule);
  machine.rs:1367 calls `ecx.binary_ptr_op_(..)`.
- **C9 path-called trait methods.** `emulate_foreign_item_inner` exists in four traits; `shims::math`,
  `shims::unix::foreign_items` and `shims::unix::linux::foreign_items` are only called by path
  (`shims::math::EvalContextExt::emulate_foreign_item_inner(this, ..)`), so they are module fns
  `emulate_foreign_item_inner(this_: MiriInterpCx, ..)` called as `math.emulate_foreign_item_inner(this, ..)`;
  `shims::foreign_items::EvalContextExtPriv`'s (called as a method, foreign_items.rs:76) stays an `InterpCx` method.
- **C10 init order.** (1) A module never value-imports *another file's* `.gen.ts`; it imports from that file's hand module
  (which re-exports it). Then every `.gen.ts` is entered through its own hand module, so a hand module may read its own
  `.gen.ts` at top level (prototype / companion assignments), even though generated modules import hand modules for
  manual impls (`debug_Provenance`, `debug_Thread`, ...). (2) A hand module never reads another Miri module's values at
  top level. (3) lib.ts loads rustc_const_eval, then every module, then installs the placeholders. The contract test loads
  every module as a fresh entry point.
- **C11 name clashes in generated code.** std `io::Error` is `io_Error` (Miri's shims/io_error.rs has its own `IoError`),
  `rustc_const_eval::interpret::MemoryKind` is `interpret_MemoryKind` (machine.rs has its own `MemoryKind` alias),
  `TerminationInfo::DataRace.ptr` (`interpret::Pointer<AllocId>`) is typed through a `fields` entry (the generator resolves
  `interpret::Pointer` to lib.rs's alias).
- **C12 lib.ts prelude.** The `pub use crate::..::{..}` items are re-exported by name; `pub use
  rustc_const_eval::interpret::*` is not (TS code imports interpreter items from rustc_const_eval / rustc_middle; a glob
  would collide with Miri's `Pointer`, `Scalar`, `MemoryKind`).
- **C13 tools/codegen change.** `types.ts` `fileModule` accepts `src/tools/miri/src/` paths (crate `miri`): needed for the
  set; review with this batch.

## Contract for interp-generic (D3 / A1)

What `impl Machine for MiriMachine` (machine.rs:1133, lane miri-machine) needs from the generic interface:

1. **Associated types as parameters** (or machine-typed members) of `Machine`, `InterpCx`, `Memory`, `Frame`,
   `Allocation`, `ImmTy`/`OpTy`/`PlaceTy`/`MPlaceTy`/`FnArg`/`Immediate`/`MemPlace`/`LocalState`: `MemoryKind = MiriMemoryKind`
   (a string union), `ExtraFnVal = DynSym` (shims/foreign_items.gen.ts), `FrameExtra = FrameExtra` (interface),
   `AllocExtra = AllocExtra` (class), `Provenance = Provenance` (`{ $: "Concrete"; alloc_id; tag } | { $: "Wildcard" }`),
   `ProvenanceExtra = ProvenanceExtra` (`{ $: "Concrete"; _0: BorTag } | { $: "Wildcard" }`), `Bytes = MiriAllocBytes`,
   `MemoryMap = MonoHashMap<AllocId, [MemoryKind<MiriMemoryKind>, Allocation<Provenance, AllocExtra, MiriAllocBytes>]>`
   (data_structures/mono_hash_map.ts; it must implement `AllocMap`). `GLOBAL_KIND = "Global"`, `PANIC_ON_ALLOC_FAIL = false`.
   `Frame<Extra>` already takes `Extra`; `Pointer<Prov>` / `Scalar<Prov>` are generic already.
2. **Provenance dispatch.** `provenance_of(prov)` (pointer.ts:126) must return `Provenance_Provenance`
   (src/miri/machine.ts, ported: `OFFSET_IS_ADDR: true`, `WILDCARD: Provenance.Wildcard`, `get_alloc_id`, `fmt`) for a
   Miri provenance value (an object). rustc_middle cannot import src/miri: provide a registration point (e.g.
   `register_object_provenance(impl)` in pointer.ts, called by src/miri/machine.ts at load, lane miri-machine) or a
   machine-carried descriptor.
3. **Descriptor-valued associated types.** Code that today hard-wires the CTFE impls needs the machine's:
   `Prov::OFFSET_IS_ADDR` without a value (`OFFSET_IS_ADDR_OF_EVERY_PROVENANCE`, pointer.ts:134; `Prov_<Prov>()` in
   allocation.ts — A1's re-ported `true` branches), `MayLeak_MemoryKind` (memory.ts:1507 reads const_eval's),
   `Display` of `M::MemoryKind` (leak reports: Miri's is `display_MiriMemoryKind`), the `AllocBytes` impl of `M::Bytes`
   (Miri's `MiriAllocBytes`), Debug of `M::Provenance` / `M::FrameExtra`. Suggested shape: readonly members of the
   machine (`ecx.machine.Provenance_impl`, `ecx.machine.MayLeak_MemoryKind`, ...), as `M::CONST` already is.
4. **Hooks**: every hook Miri overrides (machine.rs:1133-2140) exists in the port's `Machine` interface;
   `stack` is `stack_` in the port (field clash), so Miri's impl is `stack_`.
5. After interp-generic lands, root (or miri-machine) updates `tools/codegen/miri.typemap.json` (the `PORT(contract)`
   entries: `ImmTy<Provenance>`, `OpTy<Provenance>`, `PlaceTy<Provenance>`, `MPlaceTy<Provenance>`, `FnArg<Provenance>`,
   `Frame<Provenance, ..>` if `Prov` is kept), lib.ts's aliases, `MiriInterpCx = InterpCx<MiriMachine>`, and regenerates
   set `miri`.

## How to fill a stub

1. Port the file in upstream order (PORTING §3). A method declared in the module's `declare module` block: assign it
   (`InterpCx.prototype.f = function (this: MiriInterpCx, ..) {..}` / `X.prototype.f = ..`, marker above) and **delete its
   name from the `stub_methods(..)` / `stub_statics(..)` list at the end of the file** (delete the call when the list is
   empty). `install_miri_stubs()` throws at load if a name is both ported and listed, so a forgotten deletion fails every
   test that loads `src/miri/lib.ts`.
2. The declarations were translated mechanically: correct them in place (`Pending<"..">` = an unmapped type; a few
   generics or `impl Trait` parameters are approximations). Signatures others call are part of the contract: say in your
   handoff what changed. Methods named like a field of their class already carry `_` (`borrow_tracker_method_`).
3. Statics of generated classes are declared in `namespace X { .. }`: `export let f: ..` → `X.f = function ..`; `new` →
   `(X as unknown as { new: (..) => X }).new = function ..` (rustc_errors precedent).
4. Inherent methods of enums and hand types, trait impls, private fns and macros are listed in the module's
   "inventory" comment (they are not declared): enum methods go on the companion (`export const E = gen.E as typeof gen.E
   & E_methods`, as machine.ts does for `MiriMemoryKind` / `ProvenanceExtra`), trait impls are prototype methods of
   classes or `<Trait>_<Type>` impl tables (borrowck-contract rules 4-5). `VisitProvenance`: an object method
   (`interface VisitProvenance`, provenance_gc.ts) or `VisitProvenance_<T>` tables for non-objects. fns inside
   `macro_rules!` bodies are counted by coverage (e.g. `callback!`'s `visit_provenance` :2181 / `call` :2189).
5. Manual impls the generated modules import from your module are stand-ins that stop `unported` (`debug_Item`,
   `debug_UniIndex`, `debug_Thread`, `clone_VClock`, `debug_VTimestamp`, `clone_WeakFileDescriptionRef`): port them in place.
6. Needs from another lane's file that is not declared (or mis-declared): do not edit that file; add a local
   `declare module` marked `// PORT(contract): pending <lane>` and say so in your handoff (infcx-contract precedent).
7. Keep C10 (init order). Run `bunx tsc --noEmit -p .` and `bun test src/miri`.
8. Type-map changes (a `Pending` type getting a stand-in, a `fields` retype) are `tools/codegen` edits: ask root.

- **miri-driver**: the bin crate (C1; `MiriCompilerCalls`, `MiriDepCompilerCalls`, `MiriCodegenBackend` are hand types),

- **miri-race**: `VClock` (manual Clone) and `VTimestamp` (manual Debug) stand-ins.
