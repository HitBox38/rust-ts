  `LLVMIntrinsicIsOverloaded`, `LLVMGetIntrinsicDeclaration` and the wrapper `LLVMRustIsTargetIntrinsic`. Details are below.
  `declare_intrinsic`'s default arm now works for the scalar half's intrinsics, so `call_intrinsic` runs end to end through

## IR-model changes (`src/rust_ts/llvm/intrinsics.ts`)
- **The generic name table** is `GENERIC_INTRINSICS`: LLVM's `IntrinsicNameTable` for the target-independent intrinsics, 534
  entries, each with its `isOverloaded` bit.
  - I read it out of the oracle toolchain's own libLLVM.dylib in a scratch script, using `LLVMIntrinsicGetName` and
    `LLVMIntrinsicIsOverloaded` for each ID up to the first name out of sort order.
  - It is data from the oracle, like the Unicode tables. intrinsics.oracle.test.ts re-derives it.
  - An ID is the entry's index plus one, which is LLVM's own enum value.
- **Lookup** ports `lookupLLVMIntrinsicByName` (Intrinsics.cpp:677), `findTargetSubtable` and `lookupIntrinsicID`:
  - It uses the successive binary searches over dotted components, quirks included. The table is complete for generic names,
    so the answer is LLVM's.
  - A name whose first component is a target prefix (`TARGET_PREFIXES`, 19 of them) stops. Target tables are not in the model,
    and answering "not an intrinsic" there would be wrong.
- **Declarations** port `getOrInsertDeclaration`, `getType`/`DecodeFixedType`, `getIntrinsicNameImpl`, the full
  `getMangledTypeStr` and the `.invalid` rename.
  - They use `SIGNATURES`: 62 intrinsics written from Intrinsics.td at the pin, each citing its `def` line.
  - These are the intrinsics intrinsic.rs's scalar half names, plus the non-vector `call_intrinsic` uses in builder.rs:
    `*.with.overflow`, `lifetime.*`, `threadlocal.address`, `scmp`/`ucmp` and `fpto*i.sat`.
  - Declaring any other intrinsic stops, with `llir: the signature of <name> (Intrinsics.td) is not in the IR model`.
- PORT: `Intrinsic::getAttributes` is not applied, as in the model's existing `Function` (llir-core-a PORT decision 5).
- `LLVMRustUpgradeIntrinsicFunction` (AutoUpgrade.cpp) is still a stub. `intrinsic_fn` reaches it only for an `llvm.*` name
  that LLVM does not know.
- **Manifest additions: none.** Every `// llvm:` marker is in files already pinned: `llvm/lib/IR/Intrinsics.cpp`,
  `llvm/lib/IR/Core.cpp` and `llvm/include/llvm/IR/Intrinsics.td`. `LLVMRustIsTargetIntrinsic` carries a `// rustc:` marker on
  RustWrapper.cpp:1730.
- **For the llir lanes:** inst.ts has its own small `getMangledTypeStr` and `getOrInsertMemIntrinsic` for `memcpy`, `memmove`
  and `memset`. intrinsics.ts has the full mangling, and a signature table that could take those three. I left inst.ts alone
  (not my file); merging the two is a follow-up.

## `// PORT:` decisions (intrinsic.ts header unless noted)
1. **Inherent before trait.** I followed the builder.ts rule (decision 2026-11-11). In this file the receiver is a concrete
   `Builder`, so:
   - `self.store` / `load` / `trunc` / `bx.ret` / `bx.bitcast` call `store_inherent`, `load_inherent`, `trunc_inherent`,
     `ret_inherent` and `bitcast_inherent`. That means no alignment clamp on the load and store in `raw_eq`,
     `codegen_llvm_intrinsic_call`'s by-ref arguments, `volatile_load`'s temp store, the msvc slot load and
     `get_args_from_tuple`.
   - `Builder::append_block` / `build` in `gen_fn` call `append_block_inherent` and `build_inherent`.
   - `bx.const_null` / `const_struct` call `const_null_inherent` and `const_struct_inherent`.
2. **`match name { _ if simple.is_some() => .., sym::x => .., _ if starts_with("simd_") => .., sym::return_address => .., _ =>
   .. }`** becomes a `switch` after the first guard. Its `default` tests the `simd_` guard, then `return_address`, then the
   fallback, in upstream's order. The two are disjoint.
3. **`llvm_version < (23, 0, 0)`** is a lexicographic tuple compare (`version_lt`). `u64::next_power_of_two` works on numbers;
   the operands are vector lengths.
4. **`assert_matches!` in the `sve_tuple_*` arms** is `assert_scalable`. The match is exact. The failure message is a stop (see
   above).
5. **`find_attr!(tcx, def_id, RustcAutodiff(attr) => attr.clone())`** returns `Option<Option<Box<_>>>`. It is
   `{ $: "Some", _0 } | undefined` (PORTING §5), over `HasAttrs_DefId.get_attrs`.
6. **`ty::FnDef`'s args** are a `Binder<GenericArgs>` at the pin. `args.no_bound_vars().unwrap()` is
   `Binder.no_bound_vars(args, fold_GenericArgs)`, else the unwrap panic. `tcx.fn_sig(..).instantiate(..).skip_norm_wip()` is a
   module-local helper. The precedent is rustc_trait_selection's `fn_sig_instantiate`, since queries.gen.ts types the value
   `unknown`.
7. **`vtable_byte_offset as i32`** is `| 0`. **`RetagFlags::bits()`** is the number itself, since `RetagFlags` is a number
   (ssa-contract).
8. **`PointerAuthConfig::fn_attrs`** goes through attributes.ts's existing `SESSION_STOPS.fn_attrs` (cg-types-attrs). I added
   no new rustc_session stub.
9. **`codegen_msvc_try`, `codegen_wasm_try` and `codegen_gnu_try` are `export`ed** (they are private upstream), so tests can
   reach them. intrinsic.test.ts goes through `codegen_intrinsic_call` instead.
10. **IR model** (intrinsics.ts header):
    - the generic table is oracle data;
    - target tables stop;
    - signatures exist only for the scalar half's intrinsics;
    - no `Intrinsic::getAttributes`.
