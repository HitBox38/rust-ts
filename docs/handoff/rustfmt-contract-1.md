## Load order (for every later lane)

Two generated config modules import their hand module back: `macro_names.gen.ts` imports `deserialize_MacroSelector` from
`macro_names.ts`, and `file_lines.gen.ts` imports from `file_lines.ts`. Each of those hand modules augments its `.gen.ts`'s classes
when it loads. **If one of these `.gen.ts` files is evaluated first, the hand module's body runs before the classes exist (TDZ).**
`create_config.gen.ts` fails the same way, because it imports `macro_names.gen.ts` before `macro_names.ts`. Measured, loading a
module first with serde stubbed (`src/rustfmt/contracts.test.ts`):
- `macro_names.gen.ts` fails: `ReferenceError: Cannot access 'MacroName' before initialization`.
- `file_lines.gen.ts` fails: `Cannot access 'Range' …`.
- `create_config.gen.ts` fails: `Cannot access 'MacroName' …`.
- `options.gen.ts`, `lists.gen.ts`, `config/mod.ts` and the hand modules load fine.

The original handoff implied every `.gen.ts` was affected; `options.gen.ts` is not, since it imports no hand module back (review N2).
`config/mod.ts` imports the hand modules first. Everything outside `config/` must import the config through `config/mod.ts` or
`lib.ts`, never through a `config/*.gen.ts`. `contracts.test.ts` enforces this: a scan fails on any such import outside `config/`,
though an `import type` is allowed because it is erased.

## Tests and the missing serde modules

The generated config modules value-import serde (`vendor-serde-de`, wave 42), and `import { type X }` imports survive
`verbatimModuleSyntax`. So nothing can load them at runtime yet. `install_serde_stubs()` uses `bun:test`'s `mock.module` to register,
for each serde module that does not exist yet, a stand-in whose functions throw `unported("vendor-serde-de: …")`. Test files then load
the config with a dynamic `import()`. A stub is installed only while its file is missing, so the helper stops acting as soon as
vendor-serde-de lands. Delete it then. It sits in `src/rustfmt/config/` because this lane may only edit `src/rustfmt/`, and because
its `../../vendor/...` specifiers must be spelled exactly as the generated files spell them. Root may move it to `src/rust_ts/`.

## `contract_lib.d.ts`: what lib.ts and shape.ts need from modules not ported yet

Same mechanism as `contract.gen.d.ts`, written by hand. `lib.ts` imports these modules as `../rustfmt/<path>`. Each block is named by
that specifier plus `*`, and TypeScript uses a block only while no file resolves the import. **The lane that creates a module deletes
its block**, then checks `bunx tsc`. That lane may also rewrite lib.ts's specifier to `./<path>`. The signatures follow upstream at the
pin; the owning lane decides the final shape.

## `// PORT:` decisions (for root to record)

1. **Companion consts and statics.** Enum methods live on the companion const, spread from the generated one
   (`export const Density = { ...gen.Density, to_list_tactic }`, as rustc_resolve does). The generated classes get their statics
   through `Object.assign` plus `declare module` (`WidthHeuristics.null/set/scaled/from_str`, `IgnoreList.from_str`, `MacroName.new`,
   `Range.new`, `Config.default_for_possible_style_edition`, …) and their methods through the prototype. `PartialConfig` is a generated
   data-only interface, so `to_toml` and `to_parsed_config` sit on a `PartialConfig` companion const in `config/mod.ts`.
   `From` impls are named functions: `Edition.into_rustc_span`, `Edition.into_StyleEdition`, `StyleEdition.into_rustc_span`,
   `FileName_from`, `Range_from`, `String_from_MacroName`, `ErrorKind.from`.
2. **`FileLines` representation** (codegen-fmt-serde PORT 7). `_0: KeyedMap<FileName, Range[]> | undefined`. The key is
   `FileName`'s path components, so it equals `PathBuf`'s `Eq`/`Hash`. Display, `to_json_spans`, and `IgnoreList`'s Display and
   Serialize iterate std `HashMap`/`HashSet`s, which use `RandomState` and so have a per-process random order upstream; the port uses
   insertion order, which is one of the possible orders. The generated `debug_IgnoreList` and the `debug_FileLines` written here use
   `debug_HashSet`/`debug_HashMap`, which stop `unported` past one entry, as everywhere.
3. **`usize::MAX` is `Number.MAX_SAFE_INTEGER`** (`options.ts` `USIZE_MAX`, used by `WidthHeuristics::null()`), following
   promote_consts.ts and fulfillment_errors.ts. It is exact in every comparison with a real width. **It is not exact when printed:**
   `--print-config current` with `use_small_heuristics = "Off"` prints `fn_call_width` and friends, and upstream prints
   18446744073709551615. That output goes through vendor-toml's integer serializer, which stops first. Root should decide before a
   rustfmt CLI suite covers `--print-config`.
4. **`WidthHeuristics::scaled` is computed in f32**: `Math.fround` at every step, and `f32::round` rounds half away from zero.
5. **Renames for field/method clashes**: `IgnoreList::rustfmt_toml_path()` is `rustfmt_toml_path_()`, and
   `Indent::block_indent(config)` is `block_indent_(config)`. `Indent`'s `Add`/`Sub<usize>` impls are `add_usize`/`sub_usize`, next
   to `add`/`sub`.
6. **`is_nightly_channel!` is a function** (`release_channel.ts`). `CFG_RELEASE_CHANNEL` is `"nightly"`, the oracle component's
   channel, as in rustc_driver_impl. Under the nightly channel `is_stable_option_and_value` always returns true, as upstream does.
7. **`CliOptions`** is an interface with markers on its five trait fns. `load_config` takes `CliOptions | undefined`.
8. **lib.rs**: `catch_unwind` catches `Panic` only. The hook has already run at the panic (std/panic.ts), and `Unported` keeps
   unwinding. `Session`'s `Drop` is `drop()`, called where the value leaves scope (`format_snippet`). `Write` (`write_fmt`,
   `write_all`) and `VecU8` (`impl Write for Vec<u8>`) are in `lib.ts`, since src/std has no `io::Write` yet; they are candidates for
   src/std. `FormatReport.internal` (`Rc<RefCell<(…)>>`) is a shared tuple, so `clone_FormatReport` shares it.
   `format_code_block`'s `rfind`/slice indices are UTF-16 units: all of them land on ASCII characters. Its width tests use `utf8_len`.
9. **Test-only macro expansions**: `style_edition.test.ts` writes the two `style_edition_default!` invocations out by hand, inside the
   test, the way the generator expands them. `macro_names.test.ts` and `file_lines.test.ts` assert that the JSON step stops `Unported`,
   then check the rest on the value the parse would yield.
