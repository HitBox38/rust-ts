## The SVH seed: `dep_tracking_hash(true)` for the D1 core argv equals the oracle's

Observation path: a new rustc-dev probe **`optshash`** (tools/probes/optshash, built with
`bun scripts/probes.ts build optshash`) runs the oracle's own `compiler_entrypoint` with rustc's
`TimePassesCallbacks::config` effect (`trimmed_def_paths = true`, a tracked option) and prints
`sess.opts.dep_tracking_hash(true)` / `(false)` after the crate root is parsed. The port side is
src/rustc_session/dep_tracking_oracle/run.ts (the ported driver, same callbacks).
src/rustc_session/dep_tracking.oracle.test.ts compares the two (stdout, stderr, exit) on 9 cases:

- D1 core argv exactly as harness/suites.ts `CORE_ARGS(["lib"])`, cwd = upstream checkout: **crate hash equal**
  (`a66f5a6641fe6032` on this machine; `working_dir` is tracked, so the value depends on the checkout path).
- D1 core argv + `--sysroot <oracle sysroot>`: both hashes equal.
- 7 option sets on an empty `x.rs` exercising non-default values of most tracked types (dist-like `-C`/`-Z`
  flags, lints/remap, x86_64/aarch64 targets, branch protection, xray, coverage, annotate-moves, patchable
  entries, offload, llvm-module-flag tuples, codegen-retag, ... and target-error cases): all equal.

`RUST_TS_REQUIRE_PROBES=1 bun test src/rustc_session/dep_tracking.oracle.test.ts`: 9 pass.

Finding for root: without `--sysroot`, `dep_tracking_hash(false)` (the incremental hash, not the SVH) differs,
because the oracle's sysroot has `lib/rustlib/rustc-src/rust` (rustc-dev component installed) and so sets
`real_rustc_dev_source_base_dir` (TRACKED_NO_CRATE_HASH), while the port's default sysroot does not. It does not
affect the crate hash. With an explicit `--sysroot` both match.

## `// PORT:` decisions

- config.ts: `mod dep_tracking` is the exported `dep_tracking` object; a `DepTrackingHash` impl is a function
  `DepTrackingHash<T>`; `&dyn DepTrackingHash` is `DynDepTrackingHash` (value bound to its impl).
- config.ts: no derive(Hash) codegen, so the std `Hash` impls of the via-hash types are spelled out (derived enum
  `Hash` = `write_isize(discriminant)` + fields; struct = fields in order); fieldless enums without a `_discriminant`
  table get a local table citing the upstream definition line. Integer literals `Hash::hash(&0/&1, ..)` in the
  generic impls are `i32` (`write_i32`).
- config.ts: `stable_hash` sorts the `Map` keys (ASCII option names, so JS order = byte order); `OutputTypes` relies
  on its map being kept sorted (`sorted_output_types`).
- svh.ts: `Svh` as hex text (see above); `Display` ignores width/fill (`Fmt` has none).
- reachable.ts: the HIR `BodyId` is cast to rustc_middle decls.ts's pending `BodyId` for `typeck_body` (as dead.ts).
- options.gen.ts (generator): `insert!` is a generated helper `insert(name, dyn, map)` that panics on a duplicate
  after inserting, as the macro does.
