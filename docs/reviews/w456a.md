## Batch 2: ast-visit (ast_traits.rs, visit.rs, mut_visit.rs, rustc_ast_ir/visit.rs): **ACCEPT-WITH-FIXES**

Checked line by line, all matching upstream:
- **Tables:** all 57 hooks of `common_visitor_and_walkers!`. The direct/list/noop impl tables are 90/16/21. `Span` is a noop
  for `Visitor` and `visit_span` for `MutVisitor`, as the `$($mut)?` arms say. All 13 `generate_list_visit_fns!` and 13 flat-map fns.
- **Field order and `try_visit!` placement:** `walk_item_inner`, the three `WalkItemKind` impls, `walk_fn`, `Impl`,
  `MethodCall`, every `ExprKind` arm, `walk_stmt`. The mutable `Spanned` impl visits the span first, as upstream does.
  `walk_flat_map_stmt` panic text exact. `walk_filter_map_expr`, `walk_flat_map_*`.
- **`VisitorResult`:** I compared rustc_ast_ir/visit.ts myself; all three impls and `try_visit` are faithful.
  `try_visit` returns `from_residual(r)`, which is always an object for `ControlFlow`/`Result`, so a
  `ControlFlow<()>` break with an `undefined` payload still returns early (bun-checked).
- **`flat_map_in_place` shim:** same algorithm as rustc_data_structures/flat_map_in_place.rs. A 5000-case randomized
  comparison against a reference implementation found 0 mismatches.
- **ast_traits:** every `impl_has_node_id!`/`impl_has_tokens!`/`impl_has_attrs!` list, the `SUPPORTS_CUSTOM_INNER_ATTRS` values, and
  the `Stmt`/`StmtKind` delegation.
- **Marker order:** the only descents in visit.ts (8) and mut_visit.ts (5) are the `impl_visitable!`/`impl_walkable!`
  helper-macro lines (visit.rs:213/225/236/262, mut_visit.rs:165/177/188/213), as the handoff states.
- **Tests:** visit.test.ts expectations follow upstream semantics; 26/26 pass.

### Findings
1. **med**: visit.ts:785 (`declare Result`) and the prototype default (visit.ts ~1036). A `Visitor<ControlFlow<T>>` that forgets
   `override Result = VisitorResult.ControlFlow<T>()` inherits the `()` impl.
   - **Effect:** every `Break` is silently dropped (`branch` returns Continue), and the walk returns `undefined`.
   - **Upstream:** rustc rejects this at compile time (`type Result` must match the hook return types).
   - **Confirmed:** `tmp/review-w456a/ast-visit/footgun.ts`. A visitor whose `visit_id` returns `ControlFlow.Break(id)`,
     walking `(_)`, prints `result: undefined`. I reran it.
   - **Failure:** a later lane's finder visitor (`ControlFlow<Span>`) returns no result. That shows up as a missing
     diagnostic, not as an `ERROR`.
   - **Fix:** make the `()` impl's `branch` panic on any non-`undefined` value ("visitor returned a value but
     `Result` is `()`: set `override Result`"). Alternatively, make `Result` a required constructor argument when `R` is not `undefined`.
2. **med (latent, PORT-documented)**: ast_traits.ts:480-486 `AstNodeWrapper.from_mut` (ast_traits.rs:332-335) returns a wrapper that
   shares the node object, so assigning `.wrapped = x` never reaches the caller's slot.
   - **Upstream:** rustc_expand (expand.rs:2468-2480, :2607) does `*node = self.collect_*(..)` through such
     wrappers, for example the method-receiver expansion for `foo!().bar()`.
   - **Effect:** a literal port keeps the unexpanded receiver.
   - **Fix:** give the wrapper accessors that write through to the original slot (`MutRef`-based). If the PORT
     contract stays, add a hard rule in the expand lane's brief: replace in place (`Object.assign` /
     field-by-field), never reassign `.wrapped`.
3. **low**: mut_visit.ts:2187 `flat_map_in_place` has no marker (upstream flat_map_in_place.rs:18).
   - Add `// rustc: compiler/rustc_data_structures/src/flat_map_in_place.rs:18 flat_map_in_place`.
   - Better: move it into `src/rustc_data_structures/` (handoff "For root" 3).
4. **low**: `()` has two encodings: `VisitorResult.Result().output()` is `Ok(undefined)` (rustc_ast_ir/visit.ts:81), but the
   generated noop for `Result<(), ErrorGuaranteed>` is typed `Result<null, ..>` (visit.ts:406). Pick one (the generator maps `()` to `null`).
5. **low**: cleanup.
   - Unused `unported` imports at visit.ts:49 and mut_visit.ts:33.
   - Duplicate helpers `field_ref` (mut_visit.ts:221) and `field_mut` (ast_traits.ts:55): keep one, preferably in src/std next to `MutRef`.
6. **low (tests)**: add tests for:
   - a `ControlFlow<()>` Break with an `undefined` payload
   - the `Impl` walk order when `of_trait` is `Some`
   - the mutable `Spanned` impl visiting the span before the node
7. **low (process)**: `ControlFlow` still lives in rustc_ast_ir/visit.ts; move it to `src/std/ops.ts` (handoff "For root" 2).

### Findings
1. **med**: tools/codegen/types.ts:961 `isCopy` (`case "tuple": return ty.elems!.every(isCopy)`) treats a tuple of Copy
   elements as identity.
   - **Effect:** the element clone is elided and `Vec<(A, B)>` is cloned with `.slice()`. The clone then shares the tuple *arrays* with the original.
     Tuples are mutable JS arrays that the generated `MutVisitable["(T1, T2)"]` impls write into in place.
   - **Affected:** `InlineAsm.template_strs`, `InlineAsm.clobber_abis` (ast.rs:2919/2921) and `DelegationSuffixes::List` (ast.rs:4008).
   - **Confirmed:** `tmp/review-w456a/codegen/repro_tuple.ts`, which I reran. It clones an `InlineAsm` and runs a
     `visit_span`-rewriting MutVisitor over the clone only. The *original's* spans change (7→1007, 8→1008, 11→1011),
     and it prints `same tuple object: true`. In Rust the original is untouched.
   - **Scope:** latent until expansion/cfg_eval MutVisitors are ported. This is the decision-#29 hazard again, for tuples.
   - **Fix:**
     - Tuples are never identity in `isCopy` for clone purposes: rebuild them as `[c0(v[0]), c1(v[1])]` (`[...v]` when every element is a value-like Copy).
     - Regenerate, and add the repro as a derive_clone test.
2. **low**: same root cause as batch 1 finding 4 (the ast.ts:40-42 header contradicts decision #29). Fix it once.
3. **low**: walkable.gen.ts and mut_walkable.gen.ts throw a `ReferenceError` (TDZ) when entered first in a fresh
   process, before visit.ts (whose spread is at visit.ts:2087).
   - Safe today, because only visit.ts and mut_visit.ts import them.
   - **Fix:** add a header note, or a fresh-load test that enters through visit.ts.
4. **low**: tools/codegen/fixtures/rustc_ast.typedefs.json predates the probe's attribute-token change.
   - Generator output is identical, but the fixture is stale.
   - **Fix:** refresh it from the probe.
5. **low**: tokenstream.ts:358 still has the hand-written `clone_TokenCursor`, which shadows the generated one and reuses wrappers.
   - **Fix:** delete it (codegen-derive "For root" 2).
6. **low (handoff accuracy)**: the handoff says there are 8 discriminant tables; there are 9 (`TraitObjectSyntax` too).
