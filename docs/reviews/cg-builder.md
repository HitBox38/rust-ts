## Findings
No F findings.

- **N1: the IR model gives atomics no default alignment, and builder.test.ts encodes that gap.**
  - Where: `src/rustc_codegen_llvm/builder.test.ts:457`, `:459` and `:463` expect `atomicrmw ... monotonic` and `cmpxchg ...`
    with no `, align 4`. The oracle prints `, align 4`; I checked this with the pinned rustc.
  - Cause: the IR model's `LLVMBuildAtomicRMW` and `LLVMBuildAtomicCmpXchg` (`src/rust_ts/llvm/build.ts:448`, `:453`) pass no
    alignment. Upstream LLVM's Core.cpp:4530/:4552 calls `IRBuilder::CreateAtomicRMW`/`CreateAtomicCmpXchg` with `MaybeAlign()`,
    and IRBuilder then sets the alignment to `DL.getTypeStoreSize(Val->getType())`.
  - The gap is not in builder.rs, and the handoff discloses it.
  - **Root:** file it for the llir lanes in `docs/next.md`. When it is fixed, these three expectations must change to the
    oracle's text. The test then works as a tripwire.
- **N2: `load_operand`'s metadata path is untested.**
  - The `-Copt-level=2` `pick` test (`builder.test.ts:297`) calls `bx.noundef_metadata(v)` directly.
  - So none of these is exercised: `scalar_load_metadata` (builder.ts:1026, upstream :747), the `!range` end
    `wrapping_add(1)` (builder.ts:1159, upstream :862), `nonnull`/`align` metadata, `call_lifetime_intrinsic`, or the vector
    reductions.
  - I read all of them, and they are faithful. A `load_operand` test over a `bool` or `NonZero` scalar at `-O2` would cover the
    gating and the range form cheaply once ssa-operand-place lands.
- **N3: the sketch test accepts any `TypeError`.**
  - `src/rustc_codegen_llvm/skeleton.test.ts:243` matches the `Builder.build_inherent(cx, undefined)` step with
    `expect.any(TypeError)`, so any TypeError passes.
  - Pin the message, or pass a real block, so that a later regression in `build_inherent`/`with_cx` cannot hide behind it.
- **N4: an uncommented edit on the `define` line.**
  - `builder.test.ts:386` expects `define void @with_cleanup(i32 %x) personality ptr @rust_eh_personality {`.
  - The oracle's line also has `unnamed_addr #1` and `!guid !N`. Both come from the fixture's `LLVMAddFunction` and
    declare.rs/attributes.rs, not from builder.rs, so the check is sound.
  - The file header says each edit is commented at its line. This one is not.
